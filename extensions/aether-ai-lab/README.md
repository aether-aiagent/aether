# AI Lab для Aether

Автономный контур проверки поверх субагентов Aether.

Эксперимент = цель + один или несколько вариантов (тип агента + модель).
Каждый вариант запускается как **настоящий субагент** (через `pi-subagents`), в
своей сессии, не забирая ваш чат. Когда воркер закончил, **агент-ревьюер**
получает цель и отчёт воркера и возвращает строгий JSON-вердикт:

| decision | смысл |
| --- | --- |
| `accept` | работа принимается, результат уходит в основной чат |
| `revise` | почти готово, но чего-то не хватает / нет доказательств |
| `reject` | отклонено: нет результата, нет доказательств, сломано |

Вердикт содержит `confidence`, `summary`, `risks[]`, `fixes[]`. Вы видите
транскрипт и вердикт, и **в любой момент можете переопределить ревьюера**
кнопками Accept / Reject в панели лаборатории.

## Как открыть

- Меню композера → **AI Lab**
- Меню композера → **AI Lab · пресеты миссий** (сразу вкладка New с карточкой пресетов)
- Или Настройки → **AI Lab** → «Открыть лабораторию»
- Над композером появляется строка `AI Lab · N running · M awaiting review`,
  когда есть что смотреть
- Все действия ниже (пресеты, пакеты миссий, статус, отчёт) также доступны
  как операции действия `ai-lab`: `{"op": "…"}` — это единственный способ
  вызвать их из скрипта, слэш-команд расширение регистрировать не может
  (см. «Ограничения»).

Панель — это WebView-оверлей (`app.overlay`), поэтому у неё своя вёрстка, SVG и
клиентские таймеры, а каждая кнопка уходит в хост как действие `ai-lab`.

## Вкладки панели

Сверху — шапка (кнопки темы, акцента и закрытия) и строка счётчиков: запущено,
на доработке, принято, миссий. Дальше пять вкладок:

| Вкладка | Что показывает |
| --- | --- |
| ◆ Graph | карта миссий, открывается по умолчанию |
| ▤ Runs | прогоны с фильтрами и действиями |
| ✦ Experiments | эксперименты, закрепление, запуск, удаление |
| + New | конструктор эксперимента, шаблоны целей, пресеты миссий и пакеты |
| ◔ Stats | статистика по всем сохранённым прогонам и по миссиям |

### Graph

SVG-граф миссии: сверху узел цели (`MISSION GOAL` с заголовком эксперимента и
отношением «принято/всего»), под ним — узлы воркеров. Стрелки идут от воркеров
вверх и сходятся в цель; цвет стрелки берётся из статуса прогона, толщина растёт
у принятой работы, у запущенных и поставленных в очередь дуг включена анимация
потока.

На узле воркера видно точку статуса (пульсирует во время работы), тип агента или
режим, статус и бейдж вердикта. Граф строится по последним четырём экспериментам,
в каждом — до шести последних прогонов.

### Runs

- Поиск по варианту, названию эксперимента и тексту отчёта.
- Два фильтра: статус (`queued`, `running`, `done`, `failed`, `stopped`) и
  вердикт (`accept`, `revise`, `reject`, `none`).
- Массовые действия: **Run all experiments**, **Stop everything**,
  **Accept all pending**.
- Карточка прогона: точка и бейдж статуса, бейдж вердикта, шкала уверенности,
  эксперимент, режим (`subagent` / `chat`), токены, число вызовов инструментов,
  живой таймер (для запущенного) или длительность, summary вердикта, до четырёх
  пунктов `fixes`, текст ошибки.
- Отчёт воркера разбирается на секции `Result`, `Evidence`, `Verification`,
  `Risks`, `Sub-agents`; если секций нет — показывается сырой вывод.
- Кнопки: **Accept**, **Reject**, **Re-review**, **Retry w/ fixes**, **Stop**
  (у активных), **A/B**, **Отчёт .md** (см. «Отчёт одного прогона»).
- Над списком — кнопка **Статус в чат** (см. «Статус лаборатории»).

### Experiments

Список экспериментов с закреплением: закреплённые поднимаются наверх и помечаются
`★`. У каждого видны цель, варианты, число прогонов и доля принятых. Кнопки
**Run**, **Pin/Unpin**, **Delete**.

### New

- Шесть шаблонов целей: аудит модуля, починка сборки, небольшая фича,
  исследование с выбором, безопасный рефакторинг, проход по производительности.
  Шаблон подставляет текст цели в поле ввода.
- Поле цели и поле вариантов в формате `label | model key | agent type`
  (по строке на вариант).
- **Create & run** (создать и сразу запустить), **Create only**, **Export .md**,
  **Export .json**.
- Карточка **Пресеты миссий**: четыре готовых сценария одним кликом и чипы
  пакетов миссий с прогрессом (`N/parallel в работе · M в очереди`) — см.
  «Пресеты миссий» и «Пакеты миссий».
- Если черновик пришёл из пресета, под полем цели появляется readonly-поле
  «Критерии ревьюера» — видно, что именно проверит судья.
- Подсказка, доступен ли `pi-subagents`: если он выключен, прогоны пойдут через
  отдельные чаты.

### Stats

Считается по всем хранимым прогонам:

- кольцевая диаграмма доли принятых среди получивших вердикт;
- столбики Accept / Revise / Reject;
- прогоны, среднее время, токены (в тысячах), число вызовов инструментов;
- карточка **Миссии** — разбивка по экспериментам: прогоны (в работе /
  в очереди / готово / с ошибкой), принято, на доработку, отклонено, средняя
  длительность, токены, вызовы инструментов;
- оценка стоимости по фиксированной ставке ≈ $3 за 1M токенов — это
  приближение, а не счёт провайдера.

| --- | --- |
| `g` / `r` / `e` / `n` / `s` | переключить вкладку Graph / Runs / Experiments / New / Stats |
| `/` | фокус в поле поиска |

## Повтор с исправлениями и сравнение A/B

- **Retry w/ fixes** создаёт новый прогон с меткой `<label> · retry`: в промпт
  воркера добавляются `fixes` и `risks` из вердикта и сокращённый прошлый отчёт.
- **A/B** публикует в основной чат сообщение с таблицей всех прогонов того же
  эксперимента (статус, вердикт, уверенность, токены) и рекомендует лучший
  вариант по вердикту и уверенности.

## Экспорт

- **Export .md** — сводный отчёт `/workspace/ai-lab-report-<дата>.md` с целями,
  вердиктами и отчётами воркеров.
- **Export .json** — `/workspace/ai-lab-<дата>.json` (настройки, эксперименты,
  прогоны).
- Оба файла пишутся через `runtime.execute` в `/workspace`; в Termux-режиме путь
  может отличаться.
- **Отчёт .md** в карточке прогона — отдельный отчёт по одному прогону
  (см. «Отчёт одного прогона»).

## Пресеты миссий

Пресет — это готовый сценарий: цель с плейсхолдером, правила для воркера
(`workerBrief`) и критерии приёмки для ревьюера (`reviewerFocus`). Пресет не
создаёт новый вид миссии — он лишь заполняет обычный эксперимент, поэтому
принимать, повторять и сравнивать работу можно как обычно.

| id | Алиасы | Что проверяет сценарий |
| --- | --- | --- |
| `code-review` | `review`, `code-review`, `код-ревью`, `код ревью`, `ревью` | баги, гонки, утечки, обработка ошибок, мёртвый код; отчёт с `file:line` и топ-3 фиксами |
| `refactor` | `refactor`, `рефакторинг`, `рефактор` | рефакторинг без изменения поведения: тесты зелёные, список всех изменённых файлов |
| `tests` | `tests`, `coverage`, `тесты`, `покрытие`, `покрытие тестами` | тесты на самое рискованное место и показ реального прогона |
| `docs` | `docs`, `documentation`, `документация`, `доки` | README, публичные API и примеры использования — утверждения должны совпадать с кодом |

Как запустить:

- **Из панели:** вкладка **+ New** → карточка «Пресеты миссий» → клик по
  пресету. Цель и критерии ревьюера подставляются в черновик, вкладка
  переключается в конструктор — можно поправить цель и нажать **Create & run**.
- **Из настроек:** Настройки → AI Lab → «Пресеты миссий» → кнопка
  «Пресет: …» (тот же черновик) и «Статус лаборатории в чат».
- **Из меню композера:** «AI Lab · пресеты миссий» открывает вкладку New.
- **Действием `ai-lab`** — для скриптов и хоста:

```json
{ "op": "preset", "preset": "код-ревью extensions/aether-ai-lab" }
```

Строка разбирается как `<имя пресета> [область]`: имя ищется по id или алиасу
без учёта регистра и лишних пробелов, а остаток строки становится областью и
подставляется в цель вместо плейсхолдера (`<путь/модуль>`). Если области нет,
плейсхолдер остаётся, чтобы его было видно в конструкторе.

| Действие | Что делает |
| --- | --- |
| `{"op":"preset","preset":"тесты app/src"}` | создаёт миссию и сразу запускает прогоны |
| `{"op":"preset","preset":"доки","draft":true}` | только черновик, ничего не запускается |
| `{"op":"preset","preset":"refactor","goal":"…","variants":"A | модель | агент\nB","title":"…","target":"…"}` | переопределить цель, варианты, заголовок и область |
| `{"op":"presets"}` | список пресетов (`id`, `title`, `goal`, `aliases`) |
| `{"op":"create","goal":"…","preset":"refactor"}` | критерии пресета можно навесить на свою цель |

Ответ на успех: `{ok: true, preset, experiment_id, runs}` (или `draft: true` для
черновика). На неизвестное имя — `{ok: false, presets: [<все id>]}`.

`variants` принимает и строку в формате поля вариантов
(`label | model key | agent type`, по строке на вариант), и массив объектов
`{label, modelKey, agentType}`.

## Пакеты миссий (fan-out)

Пакет — это несколько миссий, запускаемых одновременно, но с ограниченным
параллелизмом: лаборатория держит не больше N воркеров в работе, остальные
ждут в очереди и стартуют по мере освобождения слотов.

| id | Алиасы | Миссии | Параллелизм по умолчанию |
| --- | --- | --- | --- |
| `audit` | `audit`, `аудит`, `аудит проекта` | линт и мёртвый код + тесты + безопасность | 3 |
| `release` | `release`, `релиз`, `перед релизом` | сборка + тесты + changelog и доки | 3 |
| `coverage` | `coverage`, `покрытие`, `тестовое покрытие` | карта покрытия + тесты на риски + метрика после | 2 |

Запуск:

- **Из панели:** вкладка **+ New** → чипы «Пакеты»; рядом виден прогресс
  `N/parallel в работе · M в очереди`.
- **Из настроек:** Настройки → AI Lab → «Пакеты миссий» → кнопка «Пакет: …»
  и поле «Параллелизм пакета».
- **Действием `ai-lab`:**

```json
{ "op": "bundle", "bundle": "аудит", "parallel": 2, "target": "extensions/aether-ai-lab" }
```

- `parallel` — 1…6; если не передан (или `0`), берётся параллелизм пакета, а
  затем настройка «Параллелизм пакета».
- `target` подставляется в цели всех миссий пакета.
- Прогресс хранится в `lab.bundles` (`pending` / `inflight`), поэтому очередь
  переживает перезагрузку: при активации расширение снова добирает слоты.
- Когда очередь пакета пуста и в работе ничего нет — приходит уведомление
  «Пакет «X» завершён.»
- `{"op":"bundles"}` — все пакеты (`id`, `title`, `description`, `parallel`,
  `tasks`) плюс `active` с прогрессом; `{"op":"bundle-status"}` — только активные.
- `{"op":"stop","run_id":"run-…"}` освобождает слот: следующая миссия пакета
  стартует сразу, остальные ждут.

## Отчёт одного прогона

Кроме сводного экспорта есть отдельный отчёт по прогону:

- кнопка **Отчёт .md** в карточке прогона (вкладка Runs);
- действие `{"op":"export-run","run_id":"run-…"}` — если `run_id` не передан,
  берётся последний прогон, который уже стартовал.

Результат: `{ok: true, path: "/workspace/ai-lab-run-<runId>-<дата>.md"}`.

В файле:

- таблица: прогон, миссия, статус, режим, агент, токены, вызовы инструментов,
  начало, конец, длительность, вердикт;
- `## Цель` — цель миссии;
- `## Вердикт` — решение, уверенность, источник, покрытие цели, риски и что
  исправить;
- `## Отчёт воркера` — вывод воркера, разделённый по секциям
  `Result` / `Evidence` / `Verification` / `Open questions` (нет секций — сырой
  текст);
- `## Другие прогоны миссии` — таблица остальных прогонов того же эксперимента
  для сравнения.

Пишется так же, как остальные экспорты, через `runtime.execute` в `/workspace`.

## Статус лаборатории

Компактная сводка в русском тексте, которую можно отправить в чат:

- кнопка **Статус в чат** (вкладка Runs и карточка «Пресеты миссий»);
- настройка «Статус лаборатории в чат»;
- действие `{"op":"status"}` → `{ok: true, text, totals}`.

Пример сообщения (`ai-lab-status`):

```
**AI Lab · статус на 12:15 UTC**
В работе: 1 · в очереди: 0 · завершено: 2 · с ошибкой: 1
Вердикты: принято 2 · на доработку 0 · отклонено 1
Средняя длительность прогона: 2м 30с · токенов 128.4k · вызовов инструментов 42

Миссии (2):
• Аудит модуля — 3 прогона, принято 2, в работе 1, ср. 3м 05с
• Рефакторинг — 1 прогон, отклонено 1, ср. 45с
```

- `{"op":"status","quiet":true}` — только вернуть текст, в чат ничего не писать.
- Длительность незавершённого прогона считается до текущего момента, поэтому в
  среднее попадают и активные прогоны.
- Та же разбивка по миссиям есть карточкой «Миссии» на вкладке **Stats**.

## Оформление

- Кнопка `◐` переключает тёмную и светлую тему, `✧` перебирает пять акцентов
  (violet, azure, emerald, amber, rose). Выбор сохраняется в настройках
  расширения и переживает перезапуск.
- Тема и акцент меняются только из панели; отдельных строк в Настройках под них
  нет.

## Модель работы без pi-subagents

Если `pi-subagents` выключен, лаборатория не ломается: каждый вариант
запускается в отдельном чате через host-мост Aether
(`app.newChat` → `app.setModel` → `app.sendMessage`), а результат читается из
состояния чата. Ревью в этом режиме идёт в отдельном чате на модели
`Reviewer model (fallback)`.

Если LLM-ревьюер недоступен вообще, используется детерминированная эвристика
(наличие секций `Result` / `Evidence`, признаки ошибок в отчёте) — она помечает
такой вердикт как `source: heuristic`.

## Создаваемые агенты

При первом запуске расширение создаёт (если их нет) два файла:

```
~/.pi/agent/agents/aether-lab-worker.md
~/.pi/agent/agents/aether-lab-reviewer.md
```

- `aether-lab-worker` — выполняет ровно одну цель и обязан отчитаться блоками
  `## Result`, `## Evidence`, `## Verification`, `## Open questions`.
- `aether-lab-reviewer` — read-only аудитор, отвечает только JSON-вердиктом.

Файлы не перезаписываются: правьте их под себя, лаборатория подхватит.

## Настройки

| Настройка | Значение |
| --- | --- |
| Auto review | автоматически отправлять завершённые прогоны ревьюеру |
| Reviewer agent type | тип субагента-судьи (по умолчанию `aether-lab-reviewer`) |
| Worker agent type | тип субагента-исполнителя (по умолчанию `aether-lab-worker`) |
| Reviewer model (fallback) | модель для ревью в чате |
| Post verdicts into the chat | публиковать вердикт как сообщение `ai-lab-verdict` |
| Export report | записать `/workspace/ai-lab-report-*.md` |
| Параллелизм пакета | сколько воркеров пакета запускать одновременно (1–6, 0 — по умолчанию пакета) |
| Clear run history | очистить историю прогонов (эксперименты остаются) |

Ниже на той же странице — кнопки «Пресеты миссий» (подставляют черновик),
«Статус лаборатории в чат» и кнопки запуска пакетов миссий.

## Данные

Всё лежит в хранилище расширения:

- `lab.experiments` — эксперименты (включая флаг `pinned`)
- `lab.runs` — прогоны и вердикты (последние 120)
- `lab.settings` — настройки страницы, тема и акцент
- `lab.open`, `lab.tab` — состояние панели и выбранная вкладка
- `lab.draft` — цель из шаблона или из пресета (включая `preset` и
  `reviewerFocus`)
- `lab.bundles` — очереди пакетов миссий (`pending` / `inflight`, до 20 заданий)

## Ограничения

- Script-расширения Aether **не могут регистрировать инструменты агента**,
  поэтому лаборатория не добавляет новый tool главному ИИ. Взаимодействие идёт
  через субагентов и сообщения `ai-lab-verdict`.
- По той же причине у расширения нет слэш-команд (`/lab …`): все новые
  возможности (пресеты, пакеты, статус, экспорт прогона) вызываются кнопками в
  панели, кнопками в Настройках и операциями действия `ai-lab`
  (`{"op": "preset" | "bundle" | "status" | "export-run" | …}`).
- Подпись «tap a node to focus its run» под графом пока не работает: нажатие на
  узел цели открывает вкладку Runs, а нажатие на узел воркера отправляет
  действие `focus-run`, которого хост ещё не обрабатывает.
- Экспорт отчёта пишет в `/workspace` через `runtime.execute`; в Termux-режиме
  путь может отличаться — тогда используйте копирование из панели.
